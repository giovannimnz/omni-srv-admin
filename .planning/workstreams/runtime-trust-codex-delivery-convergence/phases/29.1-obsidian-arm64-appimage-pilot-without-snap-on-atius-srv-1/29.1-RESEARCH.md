## Research Question

What needs to be known to plan a safe `atius-srv-1` pilot for Obsidian without Snap, using only the official ARM64 AppImage, while preserving the existing vault and integrating the result into `managed-apps`?

- Accepted asset pattern: `Obsidian-<version>-arm64.AppImage`

## Local Safety Findings

The protected user data surfaces are separate from the AppImage binary:

- Vault: `/home/ubuntu/GitHub/obsidian-vault/ideaverse`
- Profile/config: `/home/ubuntu/.config/obsidian`
- Existing vault registry: `/home/ubuntu/.config/obsidian/obsidian.json`

The plan must create a manifest/backup before first launch. It must not copy note contents, plugin data, token-like data, or profile internals into repo docs. Safe metadata is limited to paths, existence checks, file counts, `git status --short`, symlink targets, desktop file paths, and backup location.

Existing Obsidian-specific sync service:

- `obsidian-git-sync.service`
- `obsidian-git-sync.timer`

Planning implication: observe and verify these surfaces, but do not redesign sync unless a broken path creates data-loss risk.

## AppImage Runtime Findings

Ubuntu 24.04 ARM64 needs `libfuse2t64` for normal AppImage mounting. The wrapper should launch Obsidian with:

```bash
Obsidian.AppImage --no-sandbox
```

Fallback if FUSE fails:

```bash
APPIMAGE_EXTRACT_AND_RUN=1 Obsidian.AppImage --no-sandbox
```

Planning implication: install/fix may ensure `libfuse2t64 ca-certificates curl jq` are present, but must not relax global kernel/AppArmor sandbox settings for Obsidian.

## Managed-Apps Code Findings

Current managed-apps model:

- Manifest: `modules/managed-apps/configs/programs.json`
- CLI: `cli/omni/managed_apps.py`
- Docs: `docs/operations/managed-apps.md`, `modules/managed-apps/README.md`
- Script pattern: `modules/managed-apps/scripts/install-brave-browser`

Supported program kinds today:

- `apt-package-set`
- `chromium-extension`

Unsupported gap:

- No program kind exists for manually managed release assets such as AppImage.
- `_local_status()` returns unsupported kind for anything else.
- `REMOTE_PROBE` mirrors the same limitation for fleet status.
- `_upgrade_command()` only produces APT upgrade commands.
- `_post_fix()` can run `post_fix_script`, which can be reused for the Obsidian installer/fixer.

Planning implication: add a `manual-appimage` kind with local status/verify, remote probe support, and explicit manual upgrade/apply behavior. Do not use APT/Snap for Obsidian.

## Installer/Fixer Strategy

Recommended helper:

```text
modules/managed-apps/scripts/install-obsidian-arm64-appimage
```

Responsibilities:

1. Validate host architecture is ARM64/aarch64.
2. Validate host scope is `atius-srv-1` by default, unless explicitly overridden for future phases.
3. Create backup/manifest under `/var/backups/omni-managed-apps/obsidian-<timestamp>` before modifying launchers or profile-adjacent files.
4. Record safe metadata only:
   - target paths
   - symlink targets
   - sha256/version
   - `git -C /home/ubuntu/GitHub/obsidian-vault/ideaverse status --short`
   - counts, not note contents
5. Download only official asset names ending in `arm64.AppImage`.
6. Verify sha256 when GitHub asset digest is available.
7. Install under `/home/ubuntu/GitHub/Programs/obsidian/releases`.
8. Update stable symlink `/home/ubuntu/GitHub/Programs/obsidian/Obsidian.AppImage`.
9. Write wrapper `/home/ubuntu/.local/bin/obsidian`.
10. Update `/home/ubuntu/.local/bin/obsidian-tray` to resolve the new install path and remove stale Snap/`~/Applications` assumptions as primary targets.
11. Repair Desktop/menu/system launchers:
    - `/home/ubuntu/Desktop/obsidian.desktop`
    - `/home/ubuntu/.local/share/applications/obsidian.desktop`
    - `/usr/share/applications/obsidian.desktop`
12. Preserve launch through `/home/ubuntu/.local/bin/xrdp-launch` for GUI launchers.
13. Quarantine Obsidian-specific Snap remnants after backup, especially `/home/ubuntu/snap/obsidian.removed.20260622-200100`.

## Upgrade Strategy

`omni managed-apps upgrade --app obsidian` should be plan-only by default:

- Query official latest.
- Show current installed version and latest available version.
- Show download URL and expected digest.
- Show exact script command that would apply.
- Do not download or replace the AppImage unless `--yes` is present.

`omni managed-apps upgrade --app obsidian --yes` may run the Obsidian helper after the user explicitly requests it. This satisfies GOV-05: update plans are auditable and controlled by host/scope.

## Risks

- AppImage FUSE failure: mitigate with `libfuse2t64`, then fallback `APPIMAGE_EXTRACT_AND_RUN=1`.
- Electron sandbox warning: use `--no-sandbox` for the AppImage wrapper; do not relax global sandbox settings.
- Vault/profile data loss: mitigate with manifest/backup before first launch and by never editing vault contents.
- Stale Snap launcher: explicitly replace/supersede all known `.desktop` surfaces and grep for `/home/ubuntu/snap/obsidian`.
- Fleet blast radius: `obsidian` entry must be local-only to `atius-srv-1` in this phase.
- Subagent planning drift: capture all user-locked release and vault rules in `CONTEXT.md` and `PLAN.md`.
