# Phase 29.1: Obsidian ARM64 AppImage pilot without Snap on atius-srv-1 - Context

**Gathered:** 2026-06-25
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 29.1 owns a local pilot on `atius-srv-1` to restore Obsidian after Snap removal, using a non-Snap ARM64 build, preserving the existing vault and Obsidian profile, and wiring the result into the existing `managed-apps` version/source manager.

This phase must not install or replicate Obsidian on `atius-srv-2`, `atius-srv-3`, or `horistic-srv`. It prepares the pattern for later fleet rollout, but the live mutation scope is `atius-srv-1` only.

</domain>

<decisions>
## Implementation Decisions

### Install source and layout
- **D-01:** Install Obsidian under `/home/ubuntu/GitHub/Programs/obsidian`, not `/opt/obsidian`, because the user prefers manually managed programs to live under `~/GitHub/Programs`.
- **D-02:** Use the official ARM64 AppImage release asset as the preferred non-Snap source. The installer/updater must discover or verify the current release from the official Obsidian releases source at execution time instead of hard-coding an old version from discussion.
- **D-02a:** The only accepted upstream Obsidian release asset pattern is `Obsidian-<version>-arm64.AppImage` from `https://github.com/obsidianmd/obsidian-releases/releases`. Do not use `.deb`, `.tar.gz`, Snap, x86_64 AppImage, or repackaged third-party builds for this phase.
- **D-02b:** As of 2026-06-25 live verification, `releases/latest` resolves to `v1.12.7`; the matching asset is `Obsidian-1.12.7-arm64.AppImage` with sha256 `2a40943a2402cf1f38e71845f294a78d300a78ff21ea4c2103335bca7fbdcbe0`. Execution still must re-check latest before download/apply.
- **D-03:** The installed layout should keep versioned AppImages and a stable executable target. A suitable target shape is `releases/`, a stable `Obsidian.AppImage` symlink, local state metadata, and an icon/resource path under `/home/ubuntu/GitHub/Programs/obsidian`.
- **D-04:** Launch via a wrapper that passes `--no-sandbox`; install `libfuse2t64` if needed; use `APPIMAGE_EXTRACT_AND_RUN=1` only as a fallback. Do not relax global kernel/AppArmor sandbox settings for this app.

### Vault and profile protection
- **D-05:** Before opening Obsidian, create a backup/manifest covering the current vault state, `~/.config/obsidian`, current Obsidian desktop files, `~/.local/bin/obsidian`, and `~/.local/bin/obsidian-tray`.
- **D-06:** The vault path `/home/ubuntu/GitHub/obsidian-vault/ideaverse` is protected. Do not move, delete, rewrite, or copy its contents into docs/logs. Record only safe metadata such as path, `git status --short`, file counts, and backup path.
- **D-07:** Preserve `~/.config/obsidian/obsidian.json`, including the existing vault entry pointing to `/home/ubuntu/GitHub/obsidian-vault/ideaverse`.
- **D-08:** Keep the existing `obsidian-git-sync` user timer/service untouched unless verification shows it references a broken path. Any change to sync behavior is out of scope unless required to prevent data loss.

### Shortcuts and launchers
- **D-09:** Recreate/fix the Obsidian desktop shortcut at `/home/ubuntu/Desktop/obsidian.desktop`.
- **D-10:** Recreate/fix the menu launcher at `/home/ubuntu/.local/share/applications/obsidian.desktop`.
- **D-11:** Replace or supersede the broken system launcher `/usr/share/applications/obsidian.desktop`, which currently points at `/home/ubuntu/snap/obsidian/common/obsidian`.
- **D-12:** Update `~/.local/bin/obsidian` and `~/.local/bin/obsidian-tray` so both resolve to the new `/home/ubuntu/GitHub/Programs/obsidian` installation. The current wrapper still searches `~/Applications` and stale Snap paths.
- **D-13:** Preserve XRDP-friendly launch behavior through `~/.local/bin/xrdp-launch`; visual validation must use the active desktop session or x11vnc-style viewing and must not open a second XRDP session or restart XRDP automatically.

### Snap cleanup
- **D-14:** Quarantine or remove Obsidian Snap remnants after backup, including `/home/ubuntu/snap/obsidian.removed.20260622-200100` and any Obsidian launcher references to Snap.
- **D-15:** This phase only cleans Obsidian-specific Snap remnants on `atius-srv-1`. Full Snap removal from the computer/fleet is a later phase unless the Obsidian pilot explicitly uncovers a blocking dependency.

### Managed-apps integration
- **D-16:** Add Obsidian to the existing `managed-apps` model rather than creating an unrelated one-off installer.
- **D-17:** Obsidian should be `atius-srv-1` local-only in this phase. `status`, `verify`, `fix`, and `upgrade` should work locally; fleet apply must not target other hosts.
- **D-18:** Update behavior is manual-only. No auto-update timer should replace the AppImage by itself. A command may detect or plan an update, but applying it requires an explicit operator command.
- **D-19:** `managed-apps` may need a new program kind for manually managed AppImage assets, plus manifest fields for install directory, current version, release source, wrapper paths, desktop files, Snap-forbidden checks, backup path, and local-only target hosts.

### the agent's Discretion
The planner may choose the exact names of helper scripts and metadata files as long as they live under the established `modules/managed-apps/` and `cli/omni/managed_apps.py` patterns. It may also decide whether the AppImage updater is one script or split into install/fix/upgrade helpers.

</decisions>
