# 14-03: Boot/login-linger, cgroups e XRDP-safe cleanup

## objective

Validar que governor e inviolable sobem no boot/login-linger sem depender de
`default.target`, que limites ficam coerentes em slices/cgroups e que leftovers
XRDP sao tratados sem derrubar a sessao atual.

## tasks

### Task 1: login-linger and unit graph

Coletar:

```bash
loginctl show-user ubuntu
systemctl --user list-unit-files | rg "resource-governor|inviolable|omni-"
systemctl --user list-dependencies --reverse resource-governor-patcher.service
systemctl --user list-jobs
```

Garantir que:

- Linger do usuario `ubuntu` esta habilitado ou documentado como requisito.
- Governor/inviolable ficam presos apenas a timers/services proprios, nao a
  `default.target` bloqueado.
- `daemon-reload` nao derruba RDP nem PM2.

### Task 2: cgroup consistency probe

Comparar `resource-governor.env`, runtime override, slices systemd e cgroups
diretos:

```bash
systemctl --user show omni-builds.slice -p CPUQuotaPerSecUSec -p MemoryHigh -p MemoryMax
systemctl --user show omni-interactive.slice -p CPUQuotaPerSecUSec -p MemoryHigh -p MemoryMax
systemctl --user show omni-transfers.slice -p CPUQuotaPerSecUSec -p MemoryHigh -p MemoryMax
find /sys/fs/cgroup -maxdepth 6 -type d -name "omni-*" 2>/dev/null
```

Se houver drift, corrigir script/status primeiro; aplicar live apenas apos
snapshot e gate.

### Task 3: XRDP leftover treatment

Classificar PIDs XRDP/SSHD presos em cgroup antigo do watchdog:

```bash
systemctl --user status inviolable-watchdog.service --no-pager
find /sys/fs/cgroup -path "*inviolable-watchdog*" -type f -name cgroup.procs -exec sh -c 'echo "== $1 =="; cat "$1"' sh {} \;
pgrep -a xrdp
pgrep -a sshd
```

Regras:

- Nao matar PIDs XRDP/SSHD.
- Nao reiniciar `xrdp.service` sem gate; isso derruba RDP.
- Se possivel, usar nova execucao por transient unit/scope para nao gerar novos
  filhos presos.
- Se a limpeza real exigir restart, registrar como janela operacional, nao como
  acao automatica.

## acceptance_criteria

- Graph de units do governor/inviolable nao depende de `default.target` para
  operacao critica.
- Status mostra limites coerentes entre perfil base/conservador e estado live.
- Nao ha novos filhos XRDP/SSHD presos no cgroup do watchdog apos nova execucao.
- Qualquer leftover antigo fica documentado com impacto e procedimento de janela.
- Nenhuma validacao desta plan derruba RDP.

## verification

```bash
systemctl --user daemon-reload
systemctl --user is-active resource-governor-patcher.service
systemctl --user is-active resource-governor-watchdog.service
systemctl --user is-active inviolable-watchdog.timer
systemctl --user list-jobs
python3 modules/srv1-ops/scripts/resource-governor-status.py
```
