# 09-04: Cleanup timeout fix + logrotate /var/log

## objective

Corrige 2 problemas observados na missão 4h:
1. `cleanup-local.sh` retornou rc=124 (timeout 3s) 2x no log do watchdog
2. `logrotate /var/log/syslog` falha porque `/var/log` tem perm 775
   (syslog group writable, logrotate recusa por security)

## read_first

- `modules/srv1-ops/scripts/resource-governor-watchdog.py` — função `run_cmd()`
  tem `timeout: int = 3` como default. Chamada para `cleanup-local.sh` está em
  `main()` linha ~343. Aumentar para `timeout=8` resolve o cleanup.
- `/etc/logrotate.d/rsyslog` — config atual, falha com erro
  "parent directory has insecure permissions"
- `/var/log` — diretório com mode 775, owner root:syslog
- `~/.local/state/omni/mission-guardian.db` — schema com `events` table
  usada por mission-guardian para tracking

## acceptance_criteria

- `grep -n "run_cmd(\['/bin/bash', str(CLEANUP_SCRIPT)\]"`
  em `resource-governor-watchdog.py` mostra `timeout=8` (não mais default 3)
- Arquivo `modules/srv1-ops/scripts/mission-guardian-cleanup-rotate.sh`
  existe, mode 755, e:
  - Idempotente: rodar 2x não muda estado final
  - Se `/var/log` perm != 755: corrige para 755 via `sudo chmod 755 /var/log`
  - Se logrotate falha: tenta `logrotate -f /etc/logrotate.d/syslog-giovanni-emergency`
    (criado se não existir)
  - Reporta success/failure em stdout e log
- Watchdog monitora se cleanup > 30s via mission-guardian.py:
  log `cleanup-stuck` no DB events table quando `cleanup_running > 30s`
- Após rodar script, `ls -lh /var/log/syslog*` mostra:
  - syslog: size < 200M (foi rotacionado)
  - syslog.1.gz: existe (compressed previous)
- Script backup-safe: copia `/var/log` perms antes de mudar, restaura se
  algo falhar

## action

Patch em `modules/srv1-ops/scripts/resource-governor-watchdog.py`:

1. Localizar a chamada de cleanup (linha ~343):

Criar `modules/srv1-ops/scripts/mission-guardian-cleanup-rotate.sh`:
```bash
#!/usr/bin/env bash
# mission-guardian-cleanup-rotate.sh
# 2026-06-11: fix 2 problemas identificados em srv1-mission-4h:
#   1. cleanup-local.sh retornou rc=124 (timeout 3s insuficiente)
#   2. logrotate /var/log/syslog falha por perm 775 (syslog group writable)
#
# Idempotente. Rodável múltiplas vezes. Backup-safe.

set -u
LOG=/home/ubuntu/.logs/resource-governor/cleanup-rotate.log
mkdir -p "$(dirname "$LOG")"
BACKUP=/home/ubuntu/.logs/resource-governor/backups/var-log-perms-$(date +%Y%m%d_%H%M%S).bak

log() { echo "[$(date -Iseconds)] $*" | tee -a "$LOG"; }
fail=0

# === STEP 1: corrigir permissões de /var/log ===
log "STEP1: /var/log perms"
current_perm=$(stat -c '%a' /var/log)
if [ "$current_perm" != "755" ]; then
  log "  current=$current_perm -> fix to 755"
  # Backup
  mkdir -p "$(dirname "$BACKUP")"
  echo "$(stat -c '%a %U %G' /var/log)" > "$BACKUP"
  log "  backup saved to $BACKUP"
  # Apply
  if sudo chmod 755 /var/log; then
    log "  chmod 755 OK"
  else
    log "  FAIL chmod — trying via chgrp"
    sudo chgrp root /var/log && sudo chmod 755 /var/log || fail=1
  fi
else
  log "  already 755, no change"
fi

# === STEP 2: garantir config logrotate ===
LR_CONF=/etc/logrotate.d/syslog-giovanni
if [ ! -f "$LR_CONF" ]; then
  log "STEP2: creating /etc/logrotate.d/syslog-giovanni"
  sudo tee "$LR_CONF" >/dev/null <<'EOF'
/var/log/syslog
/var/log/daemon.log
/var/log/kern.log
/var/log/auth.log
/var/log/mail.log
{
    daily
    rotate 7
    size 100M
    compress
    delaycompress
    missingok
    notifempty
    create 0640 syslog adm
    su syslog adm
    sharedscripts
    postrotate
        /usr/lib/rsyslog/rsyslog-rotate
    endscript
}
EOF
  log "  created"
else
  log "STEP2: $LR_CONF already exists, no change"
fi

# === STEP 3: forçar rotação ===
log "STEP3: forcing rotation"
if sudo logrotate -f "$LR_CONF" 2>&1 | tee -a "$LOG"; then
  log "  rotation forced OK"
else
  log "  rotation may have failed (some files blocked), continuing"
fi

# === STEP 4: report ===
if [ "$fail" -eq 0 ]; then
  log "DONE_OK"
else
  log "DONE_WITH_ERRORS"
fi
```
