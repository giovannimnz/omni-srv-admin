## Logo Sizing Contract

Asset fact: the current file `/mono-atius-horizontal.svg` has a `512x512` viewBox and behaves visually as a square monogram. For this phase, treat it as a monogram only; do not allocate horizontal wordmark space.

| Viewport | Logo Size | Relation To Shell | Bottom Spacing |
|----------|-----------|-------------------|----------------|
| Mobile (`320px` to `639px`) | `40x40px` rendered size (`max-height: 40px`, `max-width: 40px`) | About `12%` of the typical `326px` inner content width on a `390px` screen; never exceed `14%` of inner width. | `8px` to the `Atius SSO` identifier, then `16px` from the identifier block to the safe-destination block. |
| Desktop (`640px+`) | `44x44px` rendered size (`max-height: 44px`, `max-width: 44px`) | About `10.8%` of the `408px` inner content width inside the `448px` shell; never exceed `11%` of inner width. | `8px` to the `Atius SSO` identifier, then `16px` from the identifier block to the safe-destination block. |

Rules:

- Use explicit width and height attributes or an equivalent fixed CSS box to prevent layout shift.
- Keep the logo centered and visually independent; do not let surrounding text define its height.
- Do not scale the logo above `44px` in the logged-out state. With the visible heading removed, the logo may grow slightly from the current `32-36px` usage, but it must not become hero branding.
- If a future true horizontal wordmark asset is introduced, it needs its own contract; this phase does not assume one.

## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tight icon offsets, inline status spacing. |
| sm | 8px | Label-to-input gaps, compact helper spacing. |
| md | 16px | Default vertical gaps, page padding on mobile. |
| lg | 24px | Shell section spacing, block separation. |
| xl | 32px | Desktop breathing room around the auth shell. |
| 2xl | 48px | Major viewport padding on tall desktop screens. |
| 3xl | 64px | Reserved for page-level spacing only; never inside the compact shell. |

Exceptions:

- Auth shell padding must map to declared tokens only: `16px` (`p-4`) on mobile and `24px` (`sm:p-6`) on `sm+`. Replace any current `20px` / `p-5` shell padding with the nearest valid token before implementation.
- Icon-only controls and text-link hit areas must keep a 44px minimum touch target.
- Secondary actions must stack vertically below `480px` width; no same-row layout is allowed for optional auth utilities on narrow screens.

## Layout Contract

- Use one auth shell only: `w-full max-w-md`, centered in `min-h-screen`, with the existing ATS rounded dark shell treatment.
- Focal hierarchy is locked after removing the visible H1: the centered logo plus `Atius SSO` is the identity anchor, the form is the primary functional focus, the safe-destination block is trust context, and the primary CTA is the dominant action.
- Keep the top stack visually short: locked-size logo, `Atius SSO`, then the safe-destination block. No visible heading/subheading pair in the logged-out state.
- Use token-based shell padding only: `p-4` on mobile and `sm:p-6` on `sm+`.
- The first viewport must contain the entire login interaction on `390x844` without secondary-control collision.
- Do not show registration upsell, trust slogans, or marketing footer copy inside the primary login viewport.
- If low-priority footer text remains, keep it at `11px`, low contrast, and outside the critical interaction cluster.
- Do not nest cards inside cards. If a `Card` wrapper is used, it stays visually transparent.

## Accessibility And Interaction

- Logged-out state must include an `sr-only` `h1` with `Entrar na Atius`.
- Status changes use `aria-live="polite"`; destructive errors use `role="alert"`.
- Spinner states must include visible text, never spinner-only feedback.
- Password visibility toggle requires an accessible name and a 44px hit target.
- Color cannot be the only indicator for safe versus invalid destinations; pair icon, label, and copy.
- Keyboard order must remain linear and predictable: destination context, fields, optional utility link, primary CTA, recovery action.
- The page must work cleanly at `320px`, `390px`, `768px`, and `1440px`.

---

## Security UI Rules

- Never display raw `redirect`, `return_to`, `state`, `code`, `id_token`, `access_token`, `refresh_token`, client secret, JWT secret, or cookie values.
- The UI may show normalized host/path only; never echo arbitrary query strings back to the user.
- Unknown host, protocol-relative URL, userinfo URL, non-HTTPS external URL, and subdomain-confusion URL must render the invalid-destination state.
- Logout copy stays user-level: `limpar cookies Atius`; internal cookie names stay out of the UI.
- Denial copy must describe access denial plainly, not mention internal permission-flag names.
