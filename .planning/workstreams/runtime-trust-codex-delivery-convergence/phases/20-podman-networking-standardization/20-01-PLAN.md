### Bugs descobertos + workarounds (documentados)

#### B20-01: `~/.local/bin/podman` wrapper injeta `--cpus 2` em subcomandos inválidos
- Em `podman volume create` e `podman network create`, `--cpus` é flag inválida → erro "unknown flag: --cpus"
- **Workaround:** usar `/usr/bin/podman` direto para `volume create` e `network create`
- Container `create` e `run` funcionam com a injeção (esses aceitam `--cpus`)
- Documentado em `references/aardvark-rootless-bug.md`

#### B20-02: Aardvark-dns 1.4.0 self-lookup NXDOMAIN
- Em algumas configs, queries internas (container → próprio nome) retornam NXDOMAIN
- Containers em netns diferente do aardvark process
- **Workaround:** `systemd-resolved` instalado + `srv<N>-podman` com `dns_enabled=true` resolve
- Pattern alternativo: `ip-static-hosts-fallback` (IPs estáticos + `extra_hosts`) para multi-container stacks — usado em plane-app v1.3.1
- Documentado em `references/aardvark-rootless-bug.md`

#### B20-03: `/run/systemd/resolve/` ausente impede container startup
- SRV-2 (e qualquer host sem systemd-resolved) tem containers que falham em subir
- Podman bind-mounts `/run/systemd` no rootless netns; tenta tmpfs em `/run/systemd/resolve/`, ENOENT
- **Fix persistente:** `apt install systemd-resolved && systemctl enable --now systemd-resolved`
- Documentado em `references/aardvark-rootless-bug.md`

#### B20-04: Network default não pode ser removida
- `podman network rm` recusa remover `default_network` (= o que tá no containers.conf)
- **Workaround:** mudar `default_network` temporariamente → `podman network rm` → recriar → restaurar
- Aplicado em SRV-3 (srv3-podman) com nome temporário `tmp-default-net`
- Documentado em `references/network-migration.md`
