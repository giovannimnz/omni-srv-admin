threat_model:
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host → Container | Container runs as root with cgroup write access — potential escape vector |
| WireGuard → FreeIPA ports | Ports 80, 443, 389, 636, 88, 464, 53 exposed to 10.1.1.0/24 — untrusted input |
| .env file → Compose | Passwords stored in plaintext on host filesystem |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Elevation of Privilege | Container runtime (cgroup mount) | mitigate | Use `seccomp:unconfined` only (NOT `--privileged`), mount cgroups read-write but no device access, read-only root filesystem |
| T-03-02 | Information Disclosure | .env file with passwords | mitigate | Set file permissions to 0600 (root-only), add .gitignore to prevent commit, use `chmod 600` after creation |
| T-03-03 | Tampering | /data volume (all FreeIPA state) | mitigate | Host directory owned by root:root with 0700 permissions, only container can write |
| T-03-04 | Information Disclosure | FreeIPA Web UI (port 443) | accept | Self-signed CA cert for internal use only, WireGuard network isolation limits exposure, no public internet access |
| T-03-05 | Spoofing | DNS port 53 exposed | mitigate | BIND configured as authoritative for atius.com.br zone only, forwarders restricted to 1.1.1.1, no open recursion |

   - `mkdir -p /home/ubuntu/docker/freeipa` (compose config directory)

   ```bash
   openssl rand -base64 32 | tr -dc 'a-zA-Z0-9!@#$%^&*' | head -c 32

   Store in variables: `DM_PASSWORD` (Directory Manager) and `ADMIN_PASSWORD` (admin user)

3. Write `/home/ubuntu/docker/freeipa/.env` with:
   ```
   IPA_DM_PASSWORD=<generated-dm-password>
   IPA_ADMIN_PASSWORD=<generated-admin-password>
   ```

4. Write `/home/ubuntu/docker/freeipa/.gitignore`:

   ```

5. Write `/var/lib/freeipa/data/ipa-server-install-options` (per research — options file pattern, NOT env var):
   ```
   --realm=ATIUS.COM.BR
   --domain=atius.com.br
   --ds-password=${IPA_DM_PASSWORD}
   --admin-password=${IPA_ADMIN_PASSWORD}
   --setup-dns
   --forwarder=1.1.1.1
   --no-ntp
   --unattended
   --mkhomedir
   --allow-zone-overlap
   --skip-mem-check
   ```
   
   NOTE: The options file uses literal password values (not variable references). Substitute the actual generated passwords into the file — `ipa-server-configure-first` reads this file as plain text via xargs, it does NOT do shell variable expansion.

   IMPORTANT: Use `1.1.1.1` as DNS forwarder (per research recommendation — more resilient than 10.1.1.2 which may change during WireGuard migration Phase 5).

   CRITICAL per D-15: NO `--external-ca` flag — use embedded Dogtag CA only.

   NOTE per research vs D-13: Use single `/data` bind mount. The research confirms the freeipa-container design routes ALL state through `/data` via symlinks. Do NOT create separate named volumes for `/etc/ipa`, `/var/lib/ipa`, etc. — this breaks the container's internal design.

  <name>Task 2: Write Docker Compose configuration with systemd support for Docker</name>

  <action>Write `/home/ubuntu/docker/freeipa/docker-compose.yml` with the following configuration:

```yaml
services:
  freeipa:
    image: freeipa/freeipa-server:almalinux-9
    container_name: freeipa-server
    hostname: ipa.atius.com.br
    restart: unless-stopped
    env_file:
      - .env
    ports:
      - "80:80"       # HTTP (certbot/ACME challenge)
      - "443:443"     # HTTPS (Web UI + API)
      - "389:389"     # LDAP
      - "636:636"     # LDAPS
      - "88:88/tcp"   # Kerberos TCP
      - "88:88/udp"   # Kerberos UDP
      - "464:464/tcp" # Kpasswd TCP
      - "464:464/udp" # Kpasswd UDP
      - "53:53/tcp"   # DNS TCP
      - "53:53/udp"   # DNS UDP
    volumes:
      - /var/lib/freeipa/data:/data:Z      # ALL state in single mount (research pattern)
      - /sys/fs/cgroup:/sys/fs/cgroup:rw   # systemd support for Docker (cgroup v2 confirmed)
    tmpfs:
      - /run
      - /tmp
    security_opt:
      - seccomp:unconfined                  # Required for systemd inside container
    dns:
      - 127.0.0.1                           # Per research Pitfall 1 — container needs to resolve its own hostname during setup
    networks:
      freeipa-net:
        ipv4_address: 172.20.0.2

networks:
  freeipa-net:
    driver: bridge
    ipam:
      config:
        - subnet: 172.20.0.0/24
          gateway: 172.20.0.1
```

Key configuration decisions (traceable to CONTEXT.md decisions):

- D-04: All 7 port pairs exposed (80, 443, 389, 636, 88/tcp+udp, 464/tcp+udp, 53/tcp+udp)
- D-05: Hostname `ipa.atius.com.br`
- D-13: Single `/data` bind mount (research overrides separate named volumes)
- D-17: `seccomp:unconfined` + cgroup mount (NOT `--privileged` — research confirms privileged is unsupported)
- DNS `127.0.0.1` — per research Pitfall 1 (circular dependency during setup)
- NO `IPA_SERVER_INSTALL_OPTS` in environment — options are in `/data/ipa-server-install-options` file (research pattern)

After writing, validate with: `docker compose -f /home/ubuntu/docker/freeipa/docker-compose.yml config`
