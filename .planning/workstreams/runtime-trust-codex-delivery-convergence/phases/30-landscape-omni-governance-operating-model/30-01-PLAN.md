# Phase 30 / Plan 30-01 — Governance responsibility matrix, access model and fallback runbook

## Objective

Define the operating model between Landscape self-hosted, Landscape SaaS fallback, Omni Fleet, Cockpit, K3s/Portainer and observability after G18 and the self-hosted Landscape migration.

## Scope

- Publish one canonical responsibility matrix.
- Declare Landscape self-hosted as the durable Ubuntu machine-management endpoint.
- Keep Omni Fleet as the central inventory/governance/audit plane.
- Keep Cockpit as host-level break-glass only.
- Keep K3s/Portainer as workload administration.
- Document access gates and fallback paths without adding secrets or mutating live services.

## Non-goals

- Implement collectors, desired-state schema or CVE/USN reporting. Those remain Phase 31 and Phase 32.
- Change live edge/auth state beyond the already-applied Landscape `/ping` fix from Phase 29 follow-up.
- Migrate apps to SSO or Domain Infrastructure. That begins in Phase 33.

## Acceptance criteria

1. GOV-01: Matrix explains ownership and boundaries for Landscape, Omni Fleet, Cockpit, K3s/Portainer and observability.
2. GOV-02: Access model lists gates for all admin surfaces and forbids anonymous direct admin-console exposure.
3. GOV-07: Fallback runbook covers SaaS, self-hosted, LXD, proxy/DNS, Omni-only and workload-control alternatives.
4. Phase state advances to Phase 31.
