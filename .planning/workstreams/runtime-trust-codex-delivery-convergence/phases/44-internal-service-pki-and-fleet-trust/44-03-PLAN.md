<tasks>

1. Add matrix verifier.
   - Files:
     - `modules/fleet-pki/scripts/verify-fleet-pki-matrix.sh`
   - Acceptance:
     - starts one temporary TLS endpoint per target host;
     - verifies from every source host to every target host;
     - validates by VPN IP and at least one DNS SAN;
     - cleans up temporary listener PIDs.

2. Run local and remote cert checks.
   - Checks:
     - root/issuing CA `CA:TRUE`;
     - leaf `CA:FALSE`;
     - `serverAuth,clientAuth`;
     - SAN coverage;
     - `openssl verify`;
     - `openssl x509 -checkend 2592000`.
   - Acceptance:
     - all four local host checks pass.

3. Run 4x4 HTTPS matrix.
   - Required:
     - 4 local file checks;
     - 12 remote source-to-target HTTPS checks;
     - cleanup proof after temporary listeners.
   - Acceptance:
     - every pair returns TLS verify code `0`;
     - hostname/IP verification is enforced;
     - results saved to redacted JSON.

4. Add service adapter plan without applying it.
   - Focus:
     - TEI example: `https://10.1.1.4:3115` requires the listener on `3115`
       to speak TLS; if TEI remains HTTP, use a reverse proxy/sidecar and move
       backend to a separate loopback/private port.
   - Acceptance:
     - docs state that PKI readiness does not automatically migrate TEI.
     - router channel stays unchanged unless a later service-specific gate
       explicitly approves HTTPS cutover.

5. Update durable knowledge stores.
   - Repo:

     - no raw private keys, tokens or passphrases are stored.
