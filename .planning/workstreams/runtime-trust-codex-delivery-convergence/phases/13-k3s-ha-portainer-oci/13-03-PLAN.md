# 13-03: Prometheus/Grafana observability + Omni Fleet control loop

## Objective

Adicionar observability ao cluster M005 sem transformar Prometheus/Grafana em
um executor de mudanças destrutivas. Prometheus coleta e avalia sinais,
Grafana visualiza, Alertmanager dispara eventos, e o Omni Fleet decide/aplica
ações com politica, idempotencia, auditoria e rollback.

## Scope

Instalar `kube-prometheus-stack` em `monitoring` depois do K3s HA estar Ready.
O stack deve ficar privado no cluster e ser publicado, se necessário, por
Cloudflare Tunnel + Access. Nenhum NodePort/LoadBalancer público.

## Control Model

| Camada | Responsabilidade |
|---|---|
| K3s `metrics-server` | Métricas recentes para Kubernetes/HPA e `kubectl top`; não é histórico operacional. |
| Prometheus | Coleta, histórico curto e regras de alerta. |
| Alertmanager | Deduplicação, grouping, silenciamento e webhook para Omni Fleet. |
| Grafana | Dashboards e análise humana. |
| Omni Fleet | Executor de políticas: pausar job, reduzir concorrência, acionar resource governor, reiniciar serviço autorizado, abrir plano de update/rollback. |

Prometheus/Alertmanager não devem executar comandos diretos no host. Qualquer
ação de controle precisa passar por `DbOmniFleet`, `TbUpdatePlans`,
`TbFleetCommands` e auditoria do M004.

## Task 0 — Production gate

Não instalar observability até:

- `13-01` ter 3 nodes Ready e Portainer funcional.
- `13-02` ter pelo menos o desenho PTP/Admin-DR documentado.
- PVC local-path e backups do K3s/Portainer definidos.
- Cloudflare Access estar decidido para qualquer UI pública.

## Task 1 — Install kube-prometheus-stack

No SRV-1, após Helm/kubectl estarem configurados:

```bash
kubectl create namespace monitoring
kubectl -n monitoring create secret generic grafana-admin \
  --from-literal=admin-user=admin \
  --from-literal=admin-password="$GRAFANA_ADMIN_PASSWORD"
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update
helm upgrade --install -n monitoring kube-prometheus-stack prometheus-community/kube-prometheus-stack \
  -f modules/k3s-ha-portainer-oci/k8s/kube-prometheus-stack-values.yaml
```

Secrets must be supplied only in the shell. Do not write admin passwords to git,
vault notes or command logs.

## Task 2 — Validate private monitoring

```bash
kubectl -n monitoring get pods,svc,pvc -o wide
kubectl -n monitoring rollout status deploy/omni-monitoring-grafana --timeout=240s
kubectl -n monitoring get prometheus,alertmanager,servicemonitor,podmonitor
kubectl -n monitoring port-forward svc/omni-monitoring-grafana 3000:80
```

Pass criteria:

- Prometheus, Alertmanager, Grafana, node-exporter and kube-state-metrics are Ready.
- Prometheus PVC Bound.
- Grafana PVC Bound.
- Services are `ClusterIP`.
- `kubectl port-forward` opens Grafana locally.

## Task 3 — Optional Grafana public access

If Grafana is exposed publicly, use a second Cloudflare hostname:

- `grafana.atius.com.br`
- service: `http://omni-monitoring-grafana.monitoring.svc.cluster.local:80`
- Cloudflare Access required.

Do not expose Prometheus or Alertmanager publicly. They remain internal unless
there is a specific admin-only tunnel with Access and a documented reason.

## Task 4 — Alertmanager to Omni Fleet bridge

Define, but do not enable destructive actions by default:

1. Alertmanager sends webhook alerts to an Omni Fleet receiver endpoint.
2. The receiver writes a non-destructive demand event/update plan in
   `DbOmniFleet`.
3. Omni Fleet policy decides whether an action is allowed.
4. Agents execute only allowlisted `TbFleetCommands`.
5. Every action writes audit events and exposes rollback/ack status.

Initial rules should create alerts only:

- disk root usage > 80%, warning; > 90%, critical
- memory available below 2 GiB for 10 minutes
- CPU/load saturation for 15 minutes
- node not ready / exporter down
- K3s API/etcd unavailable
- PgBouncer/PostgreSQL service unhealthy on SRV-1

## Task 5 — Fleet automation policy

Map alert classes to safe actions:

| Alert | Default action | Human approval |
|---|---|---|
| Disk warning | create cleanup/update plan only | required |
| Disk critical | pause non-critical batch jobs if allowlisted | required for deletion |
| Memory pressure | reduce job concurrency/resource governor profile | optional after policy proven |
| High load | defer low-priority update plans | no |
| Node not ready | notify and block cluster changes | no destructive action |
| PgBouncer/Postgres unhealthy | notify and block DB-dependent updates | required for restart |

No automatic file deletion, snapshot rollback, K3s uninstall, firewall change or
service restart is allowed in v1 without explicit approval and an audited plan.

## Acceptance

- `kube-prometheus-stack` values are versioned without secrets.
- Monitoring namespace is healthy.
- Grafana dashboard reachable privately and, if public, only through
  Cloudflare Access.
- Prometheus/Alertmanager remain `ClusterIP`.
- Alert rules produce events without direct host command execution.
- Omni Fleet control loop is documented and uses M004 DB/audit contracts.
