# Plan 35-01: Samba domain member, Kerberos auth, shares migration and smoke tests

<objective>
Move the current `Shared` Samba service from `atius-srv-2` to `atius-srv-1`
and switch authentication to FreeIPA/Kerberos without losing access to the
share data or corrupting ownership semantics.
</objective>

<tasks>

<task id="T1" type="audit">
<title>Capture current Samba/share state on `srv1` and `srv2`</title>
<action>
Record the current Samba config on `srv2`, the CIFS mount dependency on `srv1`,
the share size, user list, and the target storage path on `srv1`.
</action>
</task>

<task id="T2" type="ops">
<title>Join `atius-srv-1` to FreeIPA and stage Samba Kerberos identity</title>
<action>
Enroll `atius-srv-1` into `ATIUS.INTERNAL`, create the
`cifs/atius-srv-1.atius.internal` service principal in FreeIPA, and fetch a
Samba keytab onto `srv1`. Do not cut over the live share yet.
</action>
</task>

<task id="T3" type="ops">
<title>Stage local share data on `srv1`</title>
<action>
Create the target share directory on `srv1` and copy the existing data from
`srv2` with metadata preservation. Verify that free space and ownership remain
acceptable before switching clients to the new host.
</action>
</task>

<task id="T4" type="checkpoint:decision" gate="blocking">
<title>Checkpoint - perform live Samba cutover</title>
<action>
Stop before disabling the old Samba service on `srv2`, before enabling the new
Samba service on `srv1`, and before repointing the `srv1` mount path. Present
the exact cutover commands, rollback path, and downtime expectation.
</action>
</task>

<task id="T5" type="validation">
<title>Validate Kerberos-backed Samba access and rollback path</title>
<action>
After cutover approval, validate `smbclient -k`, ownership behavior, and the
client mount path on `srv1`. Write the summary/verification only with the
result actually reached.
</action>
</task>

</tasks>

<must_haves>
- No public Samba exposure is introduced.
- Data copy happens before share cutover.
- Samba auth on `srv1` uses FreeIPA/Kerberos.
- Existing share ownership and access semantics are preserved or any drift is
  explicitly documented before cutover.
- The live cutover remains a human checkpoint.
</must_haves>

<verification>
- Share inventory from `srv2` is captured.
- `srv1` is enrolled in FreeIPA before Samba keytab configuration.
- Target data exists on `srv1` before disabling Samba on `srv2`.
- `smbclient -k` and client mount smoke are defined for post-cutover proof.
</verification>
