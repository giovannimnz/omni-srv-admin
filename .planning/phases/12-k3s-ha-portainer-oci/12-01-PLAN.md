# 12-01: K3s HA bootstrap + Portainer exposure

## Objective

Executar a montagem inicial do cluster K3s HA em `ATIUS-SRV-1/2/3`, com
embedded etcd, K3s restrito a rede privada, Portainer CE instalado via Helm e
exposto em `portainer.atius.com.br` por Cloudflare Tunnel.

## Human Checkpoints

- Confirmar que SRV-1 ja esta em Ubuntu 24.04.
- Confirmar snapshot OCI ou backup equivalente dos 3 servidores.
- Confirmar regras OCI NSG/Security List.
- Criar o Cloudflare Tunnel remoto e fornecer token apenas no shell, nunca em arquivo versionado.
- Aprovar qualquer rollback que envolva remover `/var/lib/rancher/k3s`.

- arch `aarch64` or `arm64`

## Task 2 — Preflight all nodes

Run on each node:

```bash
hostname -s
lsb_release -ds
uname -m
timedatectl | sed -n '1,12p'
df -h /
free -h
ip -br addr
ip route get 10.1.1.1
ip route get 10.1.1.2
ip route get 10.1.1.7
```

Pass criteria:

- hostnames are `atius-srv-1`, `atius-srv-2`, `atius-srv-3`.
- all nodes are ARM64.
- time is synchronized.
- each node has route to every `10.1.1.x` peer.
- each node has >=25 GiB free root disk.

If SRV-3 fails disk gate, clean/backup before continuing.

## Task 3 — Network and firewall gate

Configure OCI NSG/Security List and host firewall so these ports are reachable
only between `10.1.1.0/24` nodes or the K3s NSG:

| Protocol | Port | Purpose |
|---|---:|---|
| TCP | 6443 | K3s API/supervisor |
| TCP | 2379-2380 | embedded etcd |
| UDP | 8472 | Flannel VXLAN |
| TCP | 10250 | kubelet metrics/API |
| TCP/UDP egress | 7844 | Cloudflare Tunnel egress |

Validation from each node to every peer:

```bash
nc -vz 10.1.1.1 6443 || true
nc -vz 10.1.1.2 6443 || true
nc -vz 10.1.1.7 6443 || true
```

Before K3s exists, closed ports are expected. The gate is that OCI and host
firewalls are configured intentionally, and public ingress is not opened.

## Task 5 — Install K3s first server on SRV-1

On SRV-1:

```bash
sudo install -d -m 700 /etc/rancher/k3s
sudo sh -c 'umask 077; openssl rand -hex 32 > /etc/rancher/k3s/cluster-token'
```

Create `/etc/rancher/k3s/config.yaml` manually on SRV-1:

```yaml
cluster-init: true
token: "<contents of /etc/rancher/k3s/cluster-token>"
node-name: "atius-srv-1"
node-ip: "10.1.1.1"
advertise-address: "10.1.1.1"
write-kubeconfig-mode: "0600"
tls-san:
  - "10.1.1.1"
  - "atius-srv-1"
disable:
  - traefik
  - servicelb
secrets-encryption: true
etcd-snapshot-schedule-cron: "0 */6 * * *"
etcd-snapshot-retention: 28
kubelet-arg:
  - "eviction-hard=nodefs.available<10%,imagefs.available<10%,memory.available<500Mi"
  - "system-reserved=cpu=500m,memory=1Gi,ephemeral-storage=5Gi"
```

Install:

```bash
curl -sfL https://get.k3s.io | INSTALL_K3S_CHANNEL=stable sh -
sudo systemctl status k3s --no-pager
sudo k3s kubectl get nodes -o wide
```

Pass criteria:

- `k3s` service active.
- SRV-1 Ready.
- no Traefik/ServiceLB pods created.

## Task 8 — Install Portainer CE LTS

On SRV-1:

```bash
kubectl get storageclass
helm repo add portainer https://portainer.github.io/k8s/
helm repo update
helm upgrade --install --create-namespace -n portainer portainer portainer/portainer \
  --set service.type=ClusterIP \
  --set tls.force=true \
  --set image.tag=lts \
  --set persistence.storageClass=local-path \
  --set nodeSelector.kubernetes\\.io/hostname=atius-srv-1
```

Validate:

```bash
kubectl -n portainer get deploy,po,svc,pvc -o wide
kubectl -n portainer rollout status deploy/portainer --timeout=180s
kubectl -n portainer port-forward svc/portainer 9443:9443
```

In another shell:

```bash
curl -kI https://127.0.0.1:9443/
```

Pass criteria:

- Portainer deployment Ready.
- PVC Bound.
- local port-forward returns HTTP 200/302.

## Task 9 — Cloudflare Tunnel for portainer.atius.com.br

Create a remotely-managed tunnel in Cloudflare named `atius-k3s-portainer`.
Copy only the tunnel token into the current shell. Do not write it to repo.

```bash
kubectl create namespace cloudflared
kubectl -n cloudflared create secret generic tunnel-token \
  --from-literal=token="$CLOUDFLARE_TUNNEL_TOKEN"
```

Apply a deployment based on Cloudflare docs:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: cloudflared
  namespace: cloudflared
spec:
  replicas: 3
  selector:
    matchLabels:
      app: cloudflared
  template:
    metadata:
      labels:
        app: cloudflared
    spec:
      affinity:
        podAntiAffinity:
          preferredDuringSchedulingIgnoredDuringExecution:
            - weight: 100
              podAffinityTerm:
                labelSelector:
                  matchLabels:
                    app: cloudflared
                topologyKey: kubernetes.io/hostname
      containers:
        - name: cloudflared
          image: cloudflare/cloudflared:latest
          env:
            - name: TUNNEL_TOKEN
              valueFrom:
                secretKeyRef:
                  name: tunnel-token
                  key: token
          command:
            - cloudflared
            - tunnel
            - --no-autoupdate
            - --loglevel
            - info
            - --metrics
            - 0.0.0.0:2000
            - run
          livenessProbe:
            httpGet:
              path: /ready
              port: 2000
            failureThreshold: 1
            initialDelaySeconds: 10
            periodSeconds: 10
```

In Cloudflare dashboard, map public hostname:

- hostname: `portainer.atius.com.br`
- service: `https://portainer.portainer.svc.cluster.local:9443`
- origin TLS verification: disabled unless a trusted internal cert is configured
- Access policy: enabled for Giovanni/admin identities

Validate:

```bash
kubectl -n cloudflared get deploy,po -o wide
kubectl -n cloudflared logs deploy/cloudflared --tail=100
curl -I https://portainer.atius.com.br/
```

Pass criteria:

- >=2 cloudflared pods Ready.
- logs show tunnel connected.
- `https://portainer.atius.com.br/` reaches Portainer through Cloudflare.

## Threat Model

| Threat | Mitigation |
|---|---|
| Public K8s API exposure | No public 6443; allow only private CIDR/NSG |
| etcd compromise | 2379-2380 private only; snapshots protected; secrets encryption enabled |
| Flannel VXLAN exposed | UDP 8472 private only |
| Portainer admin takeover | Cloudflare Access, HTTPS, no NodePort, strong admin password |
| Token leakage | Tunnel/K3s tokens never committed; redaction in docs |
| Data loss on local-path reschedule | nodeSelector to SRV-1 and PVC backup |
| Existing service outage | Traefik/ServiceLB disabled; no Docker/Podman removal |

## Rollback

If only Portainer/Cloudflare failed:

```bash
helm -n portainer uninstall portainer
kubectl delete namespace cloudflared
kubectl delete namespace portainer
```

If K3s bootstrap failed and human approves full rollback, on each joined node:

```bash
sudo /usr/local/bin/k3s-uninstall.sh
sudo rm -rf /etc/rancher/k3s /var/lib/rancher/k3s
```

Restore OCI snapshot only if uninstall is insufficient or host services break.
