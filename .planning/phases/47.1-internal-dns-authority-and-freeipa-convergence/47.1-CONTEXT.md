# Phase 47.1: Internal DNS Authority and FreeIPA Convergence - Context

**Gathered:** 2026-07-22
**Status:** Ready for planning

<domain>
## Phase Boundary

Converge the already-installed FreeIPA DNS on `atius-srv-3` into the sole
authoritative source for `atius.internal`, OCI/DRG reverse identity and IdM
service discovery. Keep CoreDNS at `10.11.1.11` as the canonical DRG-facing
resolver and keep AdGuard as the filtering/public-recursion layer through
conditional forwarding. Finish with deterministic Linux/Windows/edge client
resolution, FreeIPA/SSSD host identity and a reversible cutover.

This phase owns DNS authority and resolver convergence. It does not implement
Wayland ACP, change the two-layer local/NFS development model, remove NFS, add
plaintext SSH or create an srv-3 self-SSH path; those decisions remain in Phase
48. It also does not mutate the separate `oci_admin_http` MCP correction.

</domain>

<decisions>
## Implementation Decisions

### D-01 — Canonical host identity
- Use only these canonical mappings:
  - `atius-srv-1.atius.internal -> 10.11.1.11`
  - `atius-srv-2.atius.internal -> 10.12.1.12`
  - `atius-srv-3.atius.internal -> 10.13.1.13`
  - `horistic-srv.atius.internal -> 10.21.1.21`
- Treat `10.11.0.11`, `10.21.0.21` and other `.0.*` examples as invalid host
  addresses; they must not enter A/PTR, resolver, validation or rollback state.
- Short names are compatibility through the `atius.internal` search suffix,
  not a second DNS authority.

### D-02 — Authority split
- FreeIPA is authoritative for `atius.internal`, the four OCI/DRG reverse
  zones and IdM SOA/NS/SRV/TXT records.
- CoreDNS remains the canonical DRG resolver at `10.11.1.11`; it conditionally
  forwards the internal forward/reverse zones to FreeIPA and sends public
  recursion to AdGuard.
- AdGuard remains the home/filtering/public-recursion resolver and conditionally
  forwards the internal forward/reverse zones to FreeIPA. Do not duplicate A/PTR
  identity with AdGuard rewrites or inherited `/etc/hosts` data.
- Internal NXDOMAIN fails closed and is never retried against public DNS.

### D-03 — Private FreeIPA DNS endpoint
- Publish FreeIPA DNS on a dedicated OCI secondary private IP in
  `10.13.1.0/24`, distinct from srv-3 primary `10.13.1.13` and from the Podman
  address `10.89.53.10`.
- Do not guess or reserve an address in planning. `oci_admin_http`/OCI must
  first prove attachment, route, NSG/security-list and TCP/UDP 53 state, then
  produce a reviewed OperationPlan before mutation.
- `10.1.1.3` and the old `wg0` gateway are retired and are not rollback paths.

### D-04 — Migration and validation
- Back up FreeIPA zone/data state, CoreDNS and AdGuard before live changes.
- Prove a canary record absent from `/etc/hosts`, CoreDNS static hosts and
  AdGuard rewrites before removing any compatibility entry.
- Apply client changes in bounded canary waves with controlled TTL/cache flush,
  before/after evidence and one-host rollback.
- Linux uses systemd-resolved route-only DNS for `~atius.internal` and the PTR
  zones; Windows uses NRPT; edge clients use canonical FQDN/search suffix.

### D-05 — FreeIPA/SSSD and fleet identity
- Correct the four FreeIPA host entries and publish their exact SSH public host
  keys for SSSD fail-closed lookup.
- Fix srv-3 host-file ordering so `hostname -f` returns
  `atius-srv-3.atius.internal`.
- Standardize srv-1/srv-2/srv-3 owner identity as user `ubuntu`; retain the
  exact configured owner for Horistic. In Phase 48, srv-3 stays explicit local
  metadata at `/home/ubuntu/GitHub` and must not self-SSH.

### D-06 — Availability and phase boundary
- Do not make fleet DNS or authentication irreversibly dependent on one
  FreeIPA container. Research and plan a second failure domain/replica or keep
  a blocking stop condition until equivalent resilience and rollback are proved.
- Phase 47.1 completion is a hard dependency of Phase 48 plan 48-03 and later.
  Phase 48 plans 48-01/48-02 may continue independently.
- Keep OpenSSH encrypted with persistent multiplexing and retain NFS for
  discovery, picker, light read/diff, compatibility and fallback until Phase 48
  proves owner-local parity and rollback. No plaintext/HPN NoneSwitch.

### D-07 — Safety and concurrent ownership
- The active srv-3 Codex session `019f8850-00e7-78d2-bb66-3fba6729ea75`
  owns the `mcp oci_admin_http` correction. This phase may consume its final or
  read-only OCI evidence but must not edit the same runtime/config files.
- No secret values, Kerberos passwords/tickets, host private keys, Vault tokens
  or OCI credentials enter Git, `.planning`, Obsidian, GBrain, logs or chat.
- Live DNS, OCI, resolver, FreeIPA and firewall mutations require explicit
  backup, dry-run/OperationPlan and human checkpoint.

### the agent's Discretion
- Exact dedicated secondary private IP after OCI proof.
- Eligible FreeIPA replica host/failure domain after port, resource and service
  collision analysis.
- Exact TTL values, canary label, wave size and implementation file split,
  provided all locked safety and rollback decisions remain satisfied.

</decisions>

<code_context>
## Existing Evidence and Integration Points

- Phase 45 established DRG-first host identity and `10.11.1.11` as canonical
  resolver, but current live answers still depend on static CoreDNS/hosts data.
- CoreDNS currently binds `10.11.1.11:53`; its FreeIPA forward target still
  points at retired `10.1.1.3`, so SOA/SRV lookups fail.
- AdGuard Home currently binds the home interface plus `127.0.0.2`, has no
  internal conditional upstream and answers the four hostnames only through
  inherited host-file data.
- FreeIPA on srv-3 is healthy inside `freeipa-atius` at `10.89.53.10`, but its
  external gateway is hard-coded to retired `10.1.1.3`; the zone has stale A
  records, missing hosts and no new DRG PTR zones.
- Linux currently lists public DNS alongside `10.11.1.11`, allowing resolver
  selection drift. Windows has the suffix and tunnel DNS but no NRPT policy.
- `inventory/hosts/*.yaml` is the versioned host/IP identity source.
- The source AdGuard template lives in the separate, currently dirty
  `vpn-atius/home-proxy` checkout; execution must coordinate ownership and must
  not assume a clean pull or overwrite unrelated edits.

</code_context>

<specifics>
## Required Proof

Plan for direct and through-frontend tests of A, PTR, SOA, NS, LDAP/Kerberos
SRV/TXT, NXDOMAIN, TCP/UDP 53, DNSSEC/EDNS compatibility, client route choice,
SSSD host-key lookup, cache expiry, failure behavior and rollback. Benchmark
DNS and warm owner-alias latency without converting the observed 13–15 ms range
into an unmeasured SLA.

</specifics>
