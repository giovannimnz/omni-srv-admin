### Locked Decisions

### D-01 — Canonical host identity
- Use only these canonical mappings:
  - `atius-srv-1.atius.internal -> 10.11.1.11`
  - `atius-srv-2.atius.internal -> 10.12.1.12`
  - `atius-srv-3.atius.internal -> 10.13.1.13`
  - `horistic-srv.atius.internal -> 10.21.1.21`
- Treat `10.11.0.11`, `10.21.0.21` and other `.0.*` examples as invalid host
  addresses; they must not enter A/PTR, resolver, validation or rollback state.
- Short names are compatibility through the `atius.internal` search suffix,
  not a second DNS authority.

### D-02 — Authority split
- FreeIPA is authoritative for `atius.internal`, the four OCI/DRG reverse
  zones and IdM SOA/NS/SRV/TXT records.
- CoreDNS remains the canonical DRG resolver at `10.11.1.11`; it conditionally
  forwards the internal forward/reverse zones to FreeIPA and sends public
  recursion to AdGuard.
- AdGuard remains the home/filtering/public-recursion resolver and conditionally
  forwards the internal forward/reverse zones to FreeIPA. Do not duplicate A/PTR
  identity with AdGuard rewrites or inherited `/etc/hosts` data.
- Internal NXDOMAIN fails closed and is never retried against public DNS.

### D-03 — Private FreeIPA DNS endpoint
- Publish FreeIPA DNS on a dedicated OCI secondary private IP in
  `10.13.1.0/24`, distinct from srv-3 primary `10.13.1.13` and from the Podman
  address `10.89.53.10`.
- Do not guess or reserve an address in planning. `oci_admin_http`/OCI must
  first prove attachment, route, NSG/security-list and TCP/UDP 53 state, then
  produce a reviewed OperationPlan before mutation.
- `10.1.1.3` and the old `wg0` gateway are retired and are not rollback paths.

### D-04 — Migration and validation
- Back up FreeIPA zone/data state, CoreDNS and AdGuard before live changes.
- Prove a canary record absent from `/etc/hosts`, CoreDNS static hosts and
  AdGuard rewrites before removing any compatibility entry.
- Apply client changes in bounded canary waves with controlled TTL/cache flush,
  before/after evidence and one-host rollback.
- Linux uses systemd-resolved route-only DNS for `~atius.internal` and the PTR
  zones; Windows uses NRPT; edge clients use canonical FQDN/search suffix.

### D-05 — FreeIPA/SSSD and fleet identity
- Correct the four FreeIPA host entries and publish their exact SSH public host
  keys for SSSD fail-closed lookup.
- Fix srv-3 host-file ordering so `hostname -f` returns
  `atius-srv-3.atius.internal`.
- Standardize srv-1/srv-2/srv-3 owner identity as user `ubuntu`; retain the
  exact configured owner for Horistic. In Phase 48, srv-3 stays explicit local
  metadata at `/home/ubuntu/GitHub` and must not self-SSH.

### D-06 — Availability and phase boundary
- Do not make fleet DNS or authentication irreversibly dependent on one
  FreeIPA container. Research and plan a second failure domain/replica or keep
  a blocking stop condition until equivalent resilience and rollback are proved.
- Phase 47.1 completion is a hard dependency of Phase 48 plan 48-03 and later.
  Phase 48 plans 48-01/48-02 may continue independently.
- Keep OpenSSH encrypted with persistent multiplexing and retain NFS for
  discovery, picker, light read/diff, compatibility and fallback until Phase 48
  proves owner-local parity and rollback. No plaintext/HPN NoneSwitch.

### D-07 — Safety and concurrent ownership
- The active srv-3 Codex session `019f8850-00e7-78d2-bb66-3fba6729ea75`
  owns the `mcp oci_admin_http` correction. This phase may consume its final or
  read-only OCI evidence but must not edit the same runtime/config files.
- No secret values, Kerberos passwords/tickets, host private keys, Vault tokens
  or OCI credentials enter Git, `.planning`, Obsidian, GBrain, logs or chat.
- Live DNS, OCI, resolver, FreeIPA and firewall mutations require explicit
  backup, dry-run/OperationPlan and human checkpoint.

## Summary

O planner deve tratar esta fase como migração de autoridade e runtime state, não como simples edição de arquivos: primeiro tornar o estado desejado inventory-driven e obter backup/OCI OperationPlan; depois corrigir FreeIPA e provar a autoridade diretamente; só então trocar CoreDNS, AdGuard e clientes em waves reversíveis. ## Recommended Architecture

```text
Linux fleet -- route-only resolved ----> CoreDNS 10.11.1.11 -- internal zones --+
Windows ---- NRPT ---------------------> CoreDNS 10.11.1.11                   |
Home/edge -- FQDN/search suffix -------> AdGuard ----------- internal zones ---+--> dedicated srv-3 secondary IP --> FreeIPA DNS 10.89.53.10 (container-only)
CoreDNS -- public names --> AdGuard --> filtered public upstreams              |
AdGuard/CoreDNS <-- authoritative NXDOMAIN; never retry internal names publicly+
```

O secondary IP termina somente no private service path aprovado; `10.89.53.10` não vira endereço de cliente. O nome/IP exato do endpoint e o mecanismo host→container devem ser materializados após o read-only proof, sem alterar por suposição outros listeners IdM. [VERIFIED: 47.1-CONTEXT.md]

## Current Drift

- CoreDNS responde A/PTR estático em `10.11.1.11:53`, mas SOA/SRV de `atius.internal` timeout porque ainda encaminha ao aposentado `10.1.1.3`. [VERIFIED: approved recovery evidence]
- AdGuard não tem conditional internal upstream e as quatro respostas observadas vêm de host-file herdado; rewrites duplicados são proibidos. [VERIFIED: approved recovery evidence]
- `freeipa-atius` está saudável em `10.89.53.10`, porém a exposição externa, A records e reverse zones ainda refletem/incompletam o modelo antigo; SRV IdM internos permanecem válidos. [VERIFIED: approved recovery evidence]
- No srv-3, `hostname -f` retorna short name por ordenação do hosts file; SSSD não retorna as quatro host keys. [VERIFIED: approved recovery evidence]
- Linux mantém `10.11.1.11` e DNS público coiguais; Windows tem suffix/tunnel DNS, mas não NRPT. [VERIFIED: approved recovery evidence]

1. **Wave 0 — contract/preflight:** add desired-state config, validator and tests; snapshot versions, dirty-tree hashes, live config/state and backups; assert canary absent everywhere; ingest read-only OCI evidence. [VERIFIED: 47.1-CONTEXT.md]

3. **Wave 2 — resolver frontends:** patch CoreDNS first, then AdGuard under separate ownership; prove canary, full record matrix, public recursion path, NXDOMAIN fail-closed and TCP/UDP before removing any static duplicate. [VERIFIED: REQUIREMENTS.md]
4. **Wave 3 — clients:** canary one Linux host, then remaining Linux, then W11 NRPT, then edge clients; flush only bounded caches and rehearse rollback after each class. [VERIFIED: 47.1-CONTEXT.md]
5. **Wave 4 — resilience/closeout:** execute replica/failure test, SSSD lookup matrix, latency sampling and rollback rehearsal; if resilience is unproved, retain IDA-07 stop condition and keep 48-03 blocked. [VERIFIED: REQUIREMENTS.md]

## Failure Modes and Rollback

| Failure | Stop/rollback |
|---|---|
| Wrong/unreachable secondary IP or port 53 | Abort before DNS edits; use OperationPlan rollback. Never fall back to `10.1.1.3`. [VERIFIED: 47.1-CONTEXT.md] |
| Broken FreeIPA zone/SRV/PTR | Restore exported IPA data/zone state; re-run direct matrix before frontends. [VERIFIED: REQUIREMENTS.md] |
| Forward loop, timeout or public leak | Restore frontend backup; verify authoritative NXDOMAIN and trace selected upstream. [VERIFIED: REQUIREMENTS.md] |
| Dirty AdGuard checkout conflict | Stop, coordinate its owner, apply a minimal patch; never clean/reset/pull over unrelated edits. [VERIFIED: 47.1-CONTEXT.md] |
| Client loses internal/public resolution | Restore that host's resolved/NRPT snapshot, flush its cache, and halt the wave. [VERIFIED: 47.1-CONTEXT.md] |
| SSH host-key mismatch/missing SSSD result | Fail closed; restore/correct IPA host attributes, never enable TOFU or disable strict checking. [VERIFIED: 48-03-PLAN.md] |
| Single FreeIPA container/failure domain unavailable | Do not complete IDA-07 or release 48-03 until replica/equivalent resilience and recovery are proven.
