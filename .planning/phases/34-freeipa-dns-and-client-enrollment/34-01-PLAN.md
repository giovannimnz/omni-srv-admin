# Plan 34-01: WireGuard/CoreDNS/FreeIPA DNS Coexistence and Linux Client Enrollment

<objective>
Validate the first safe FreeIPA client-enrollment path without enrolling real fleet hosts yet.
The implementation must prove that FreeIPA DNS is reachable on the private Podman network, that a disposable Linux client can resolve and authenticate against `ipa.atius.internal`, and that the production rollback path is documented before any `atius-srv-*` or `horistic-srv` host joins the realm.
</objective>

<task id="T2" type="ops">
<title>Run disposable FreeIPA client smoke on SRV3 Podman network</title>
<read_first>
- docs/domain/freeipa-foundation.md
- .planning/phases/34-freeipa-dns-and-client-enrollment/34-01-PLAN.md
</read_first>
<action>
On `atius-srv-3`, create or replace a disposable container named `freeipa-client-test` from `docker.io/library/almalinux:9` on `freeipa-atius-net`, with hostname `client1.atius.internal` and DNS server `10.89.53.10`. Install `freeipa-client`, `bind-utils`, and `krb5-workstation` inside the disposable container. Verify DNS resolution for `ipa.atius.internal`, attempt unattended enrollment to `ATIUS.INTERNAL` using the root-only FreeIPA bootstrap secret on SRV3, and capture whether SSSD/systemd constraints block enrollment in the container. Do not expose ports, do not mutate host DNS, and do not enroll real fleet hosts.
</action>
<acceptance_criteria>
- `dig +short ipa.atius.internal @10.89.53.10` inside the disposable client returns `10.89.53.10`.
- If enrollment succeeds, `kinit admin` or `ipa ping` succeeds from the disposable client.
- If enrollment fails due to container/systemd/SSSD constraints, the failure is documented as a Phase 34 blocker without mutating real hosts.
- No `realm join`, `ipa-client-install`, SSSD config, DNS resolver, or `/etc/hosts` changes are applied to the four managed hosts.
</acceptance_criteria>
</task>
