# 13-01: M005 No-Cost Release Gates

## Objective

Fechar os blockers restantes do M005 sem custo recorrente novo: substituir o
gate de snapshots OCI por disaster recovery via GDrive, aceitar `local-path`
com backup/restore para este milestone, validar Tailscale como fallback
operacional, configurar Cloudflare Access se disponivel sem custo, recuperar
Jenkins via Podman e habilitar Ubuntu Pro/ESM Apps nos 3 SRVs.

## Human Checkpoints

- Nao gravar tokens Cloudflare, Tailscale, Ubuntu Pro ou credenciais Jenkins em
  git, `.planning`, logs ou vault.
- Nao aplicar `apt upgrade` amplo sem janela explicita; este plano valida e
  habilita repos ESM, mas upgrades em massa sao gate separado.
- Nao trocar K3s/flannel/etcd de `wg0` para Tailscale neste milestone.
- Nao remover Apache Basic Auth ate Cloudflare Access retornar validação 200/302
  com Access no caminho publico.

## Secret Handling Rules

Apply these rules before any live execution task:

1. Run all secret-bearing shell blocks with `set +x`.
2. Do not echo environment variables, tokens, API keys or generated auth URLs.
3. Do not pass long-lived API keys directly in process arguments when an API
   supports reading headers/config from a protected temporary file.
4. If a temporary credential file is required, create it under `/dev/shm` with
   `umask 077`, remove it with `rm -f` before the task exits, and never copy it
   into repo/vault/log paths.
5. Before every commit, run a value-based leak check for loaded secrets:

```bash
set +x
git_diff="$(git diff --cached -- . || true)"
for name in CF_GLOBAL_API_KEY CF_API_TOKEN TAILSCALE_AUTHKEY UBUNTU_PRO_TOKEN UA_TOKEN PRO_ATTACH_TOKEN; do
  value="${!name:-}"
  if [ -n "$value" ] && printf '%s' "$git_diff" | grep -Fq "$value"; then
    echo "secret leak detected for $name" >&2
    exit 1
  fi
done
unset git_diff value
```

6. Also scan for accidental secret-shaped strings before commit:

```bash
git diff --cached -- . | rg -i "([a-z0-9_]*(token|secret|password|api[_-]?key)[a-z0-9_]*\\s*[:=]\\s*['\\\"]?[A-Za-z0-9_./+=:-]{12,})" && exit 1 || true
```

## Task 2 - Promote GDrive disaster recovery gate

Extend the existing PVC backup flow so the accepted gate is auditable:

1. create a fresh local K3s/PVC backup bundle on SRV-1;
2. generate or verify `SHA256SUMS`;
3. upload/copy the bundle to the configured GDrive backup path using `rclone`
   direct copy, not heavy writes through `~/GDrive`;
4. verify the GDrive copy by listing/checking size and checksum material;
5. record the GDrive path in planning and, if safe, in `DbOmniFleet/TbConfigItems`.

Preferred commands:

```bash
modules/k3s-ha-portainer-oci/scripts/backup-local-path-pvcs.sh
rclone copy /home/ubuntu/.backups/k3s-local-path/<bundle> giovanni-drive:ATIUS-SRV/SRV-1/Backup/k3s-local-path/<bundle> --checksum --progress
```

Verify:

```bash
test -f /home/ubuntu/.backups/k3s-local-path/<bundle>/SHA256SUMS
rclone lsf giovanni-drive:ATIUS-SRV/SRV-1/Backup/k3s-local-path/<bundle> | sort
```

Acceptance criteria:

- GDrive contains the bundle or an explicit failure reason is recorded;
- local and remote artifact names are enough for restore without OCI console;
- restore drill references the GDrive path.

## Task 3 - Validate Tailscale fallback on SRV-1/SRV-2/SRV-3

Install/configure Tailscale only as a secondary management plane:

- verify whether `tailscale` is installed and logged in on each SRV;
- install if missing using the official package flow;
- authenticate without logging secrets;
- apply/recommend ACL limiting the 3 nodes plus admin user;
- validate node-to-node ping and SSH/Fleet path over Tailscale IPs;
- record names/IPs in the network map.
- record ACL evidence without secrets:
  - preferred: sanitized ACL JSON or ACL summary stored in planning/vault;
  - acceptable fallback: explicit note that the current tailnet ACL is
    intentionally managed in the Tailscale admin console, with allowed identities
    and allowed ports listed in text.

Minimum M005 ACL intent:

- source identities: Giovanni/admin operator identity only, plus the three
  tagged server nodes when node-to-node access is required;
- destination nodes: SRV-1, SRV-2, SRV-3 Tailscale IPs only;
- allowed ports: `22/tcp` for SSH, `6432/tcp` for PgBouncer admin/client checks
  when explicitly needed, and narrowly scoped diagnostic ports used by Fleet;
- excluded: public access, wildcard `*:*` access, and using Tailscale as
  flannel/etcd/K3s transport in M005.

Verify:

```bash
tailscale status
tailscale ping <srv-peer>
ssh ubuntu@<tailscale-ip> hostname
```

Acceptance criteria:

- all three SRVs appear in the tailnet;
- at least one direct management check succeeds in every direction or a specific
  blocked path is documented;
- ACL policy is recorded or explicitly accepted as already controlled in the
  Tailscale admin console, including allowed users/groups, nodes and ports;
- if the admin-console ACL cannot be exported, the final gate review must record
  the minimum ACL intent above and state who accepted it;
- docs state K3s still depends on WireGuard for M005.

## Task 4 - Configure Cloudflare Access for edge admin

Use Cloudflare credentials from the operator environment without printing them.

Target apps:

- `portainer.atius.com.br`
- `docker.atius.com.br`
- `grafana.atius.com.br`
- `jenkins.atius.com.br`

Implementation notes:

- prefer Cloudflare API over browser automation for repeatability;
- use browser/Camoufox only if Access setup is impossible through API;
- keep Apache Basic Auth active until Access is validated;
- if Access is unavailable or paid-only in the account, record Basic Auth as the
  accepted no-cost fallback for M005.
- load Cloudflare credentials in a non-verbose shell and never print values:

```bash
set +x
source ~/.zshrc >/dev/null 2>&1
: "${CF_ACCOUNT_ID:?missing CF_ACCOUNT_ID}"
: "${CF_ZONE_ID_ATIUS:?missing CF_ZONE_ID_ATIUS}"
: "${CF_AUTH_EMAIL:?missing CF_AUTH_EMAIL}"
: "${CF_GLOBAL_API_KEY:?missing CF_GLOBAL_API_KEY}"
umask 077
cf_headers="$(mktemp /dev/shm/cf-headers.XXXXXX)"
{
  printf 'X-Auth-Email: %s\n' "$CF_AUTH_EMAIL"
  printf 'X-Auth-Key: %s\n' "$CF_GLOBAL_API_KEY"
  printf 'Content-Type: application/json\n'
} > "$cf_headers"
# Use curl -H "@$cf_headers" ... and remove the file in a trap.
```

The final implementation must use `trap 'rm -f "$cf_headers"' EXIT` or an
equivalent cleanup before making API calls.

Verify:

```bash
curl -skI https://portainer.atius.com.br/
curl -skI https://grafana.atius.com.br/
curl -skI https://jenkins.atius.com.br/
```

Acceptance criteria:

- public no-auth requests are blocked by Cloudflare Access or Basic Auth;
- no Cloudflare token appears in shell output, git diff or logs;
- edge auth decision is recorded in the gate review.

## Task 6 - Enable and validate Ubuntu Pro ESM Apps

For each SRV:

1. run `pro status --all`;
2. if unattached, attach using the Ubuntu Pro token from a non-logged secret
   source;
3. if `esm-apps` is disabled, run `sudo pro enable esm-apps`;
4. validate `esm-apps` and `esm-infra` status;
5. do not run broad `apt upgrade` without a separate maintenance decision.

SRV-3 is the known attach gap from pre-flight. If no token is available in the
environment, do not fake closure; keep the gate blocked and record that an
Ubuntu Pro token/attach path is required.

Safe attach pattern:

```bash
set +x
: "${UBUNTU_PRO_TOKEN:?load token from a non-logged secret source first}"
ssh ubuntu@10.1.1.7 'sudo pro attach --token-stdin' <<<"$UBUNTU_PRO_TOKEN"
unset UBUNTU_PRO_TOKEN
```

Do not put the token in the SSH command line, logs, planning docs or shell
history.

Verify:

```bash
pro status --all
pro status --format json
```

Acceptance criteria:

- SRV-1/SRV-2/SRV-3 are attached to Ubuntu Pro or have an explicit recorded
  reason why not; SRV-3 currently needs attach handling;
- `esm-apps` is `enabled` on all attached SRVs;
- no Ubuntu Pro token is committed or printed.
