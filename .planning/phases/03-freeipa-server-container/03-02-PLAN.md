<task type="auto">
  <name>Task 1: Start FreeIPA container and monitor unattended installation</name>
  <files>/home/ubuntu/docker/freeipa/docker-compose.yml</files>
  <action>Launch the FreeIPA container and monitor the installation process:

1. Pre-launch verification:
   ```bash
   # Confirm prerequisites
   test -f /home/ubuntu/docker/freeipa/.env && echo "OK: .env exists"
   test -f /var/lib/freeipa/data/ipa-server-install-options && echo "OK: install options exist"
   docker image inspect freeipa/freeipa-server:almalinux-9 >/dev/null 2>&1 && echo "OK: image present"
   ss -tlnp | grep -E ':(80|443|389|636|88|464|53) ' || echo "OK: all ports free"
   ```

2. Start the container:
   ```bash
   cd /home/ubuntu/docker/freeipa && docker compose up -d
   ```

3. Monitor installation progress (this takes 3-8 minutes):
   ```bash
   docker logs -f freeipa-server
   ```
   
   Key milestones to watch for in logs:
   - "Configuring directory server" (389 DS setup)
   - "Configuring Kerberos KDC" (MIT Kerberos setup)
   - "Configuring certificate server" (Dogtag CA — this is the longest step)
   - "Configuring DNS (BIND)" (internal DNS setup)
   - "Server is complete" or "The ipa-server command was successful"

4. Wait until the container reports healthy. Check with:
   ```bash
   docker ps --filter name=freeipa --format '{{.Status}}'
   ```
   
   The container is ready when `docker exec freeipa-server ipa ping` returns "ipa: INFO: The ipa command was successful"

5. If the container exits or shows errors:
   - Check logs: `docker logs freeipa-server --tail 100`
   - Common failures: DNS resolution (check /etc/hosts), memory (check `--skip-mem-check` in options), FIPS crypto (verify host policy is DEFAULT)
   - Recovery: `docker stop freeipa-server && docker rm freeipa-server && rm -rf /var/lib/freeipa/data/* && docker compose up -d` (fresh start)

   IMPORTANT: Do NOT proceed to Task 2 until `ipa ping` succeeds. The installation is sequential — services depend on each other.
  </action>
  <verify>
    <automated>docker exec freeipa-server ipa ping 2>/dev/null | grep -q "successful"</automated>
  </verify>
  <done>FreeIPA container is running, ipa ping returns successful, all services (Directory Server, Kerberos, CA, DNS, HTTP) are operational</done>

<task type="auto">
  <name>Task 2: Verify FreeIPA core services — CLI, Web UI, realm, DNS, CA</name>
  <files></files>
  <action>Run comprehensive verification of all FreeIPA services that were just installed:

1. **Container health check** (FIPA-01):
   ```bash
   docker ps --filter name=freeipa --format '{{.Names}}\t{{.Status}}'
   ```

2. **CLI accessibility** (FIPA-02):
   ```bash
   docker exec freeipa-server ipa user-find admin
   ```
   Should return the default admin user created during install.

3. **Realm verification** (FIPA-03):
   ```bash
   docker exec freeipa-server ipa realm-show
   ```
   Must return `ATIUS.COM.BR`.

4. **DNS verification** (FIPA-04):
   ```bash
   docker exec freeipa-server host ipa.atius.com.br
   docker exec freeipa-server nslookup ipa.atius.com.br 127.0.0.1
   docker exec freeipa-server ipa dnszone-show atius.com.br
   ```
   DNS must resolve ipa.atius.com.br to the container's IP (172.20.0.2) and the zone must exist.

5. **CA verification** (FIPA-05):
   ```bash
   docker exec freeipa-server ipa cert-show 1
   docker exec freeipa-server ipa ca-show
   ```
   Should show the IPA CA (Certificate Authority) and certificate ID 1.

6. **Web UI accessibility** (FIPA-02):
   ```bash
   curl -k -s -o /dev/null -w "%{http_code}" https://10.1.1.1/ipa/ui/
   ```
   Should return 200 (or 302 redirect to login page).

7. **Kerberos verification** (bonus — confirms auth stack):
   ```bash
   docker exec freeipa-server bash -c "echo 'password' | kinit admin" 2>/dev/null || docker exec freeipa-server kinit admin <<< "$(grep IPA_ADMIN_PASSWORD /home/ubuntu/docker/freeipa/.env | cut -d= -f2)"
   docker exec freeipa-server klist
   ```

If any check fails, document the specific failure and check container logs: `docker logs freeipa-server --tail 50`
  </action>

  </verify>
  <done>Realm is ATIUS.COM.BR, DNS resolves ipa.atius.com.br, CA certificate exists and is accessible, CLI responds to commands, Web UI accessible on HTTPS</done>
