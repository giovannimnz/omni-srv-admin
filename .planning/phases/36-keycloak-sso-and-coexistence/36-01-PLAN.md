# Plan 36-01: Keycloak LDAP federation, OIDC endpoint and Apache SSO coexistence smoke

<objective>
Deploy Keycloak on `atius-srv-1`, federate it to FreeIPA, validate a working
OIDC path, and prove that the existing Apache SSO surface remains unaffected.
</objective>

<tasks>

<task id="T1" type="audit">
<title>Capture current auth/port baseline on `srv1`</title>
<action>
Record Apache listeners, current legacy auth entrypoints, Java/runtime posture,
and the candidate private ports for Keycloak.
</action>
</task>

<task id="T2" type="ops">
<title>Install Keycloak natively on `srv1` with isolated private ports</title>
<action>
Install a supported Keycloak build on `srv1`, create a systemd-managed runtime,
and keep it on non-conflicting private ports first.
</action>
</task>

<task id="T3" type="ops">
<title>Federate Keycloak to FreeIPA and validate user/attribute lookup</title>
<action>
Configure Keycloak federation against FreeIPA with a safe read-first mode and
prove that domain users appear with the expected attributes.
</action>
</task>

<task id="T4" type="validation">
<title>Expose controlled OIDC smoke path and verify coexistence</title>
<action>
Publish a safe Keycloak route, validate the OIDC discovery/auth path, and prove
that the legacy Apache SSO surfaces still answer unchanged.
</action>
</task>

<task id="T5" type="tracking">
<title>Write closeout artifacts and update planning state honestly</title>
<action>
Write summary/verification/runbook artifacts and update planning files only
with the result actually reached.
</action>
</task>

</tasks>

<must_haves>
- Keycloak must not reuse the current Apache production auth path.
- FreeIPA remains the identity source of truth.
- The first federation mode should avoid user writes back into FreeIPA.
- `auth.atius.com.br` is not published until local/private smoke passes.
- Legacy Apache SSO remains intact throughout the phase.
</must_haves>

<verification>
- Keycloak service is healthy on `srv1`.
- FreeIPA federation proves domain user visibility.
- OIDC discovery endpoint answers correctly.
- Legacy Apache SSO entrypoints still respond unchanged.
</verification>
