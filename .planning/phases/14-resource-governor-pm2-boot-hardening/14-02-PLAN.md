# 14-02: PM2 boot canonicalization e stale jobs

## objective

Definir e implementar um caminho canonico para PM2 subir ATS/Horistic no boot,
removendo referencia a arquivo inexistente e drenando jobs presos sem matar os
apps ativos.

## read_first

- `14-CONTEXT.md`
- `modules/srv1-ops/scripts/inviolable-watchdog.sh`
- `modules/srv1-ops/scripts/resource-governor-status.py`
- `/home/ubuntu/GitHub/Atius-Capital/ats/ecosystem.config.js`
- `/home/ubuntu/GitHub/Atius-Capital/horistic/ecosystem.config.js`
- `systemctl --user cat ats-pm2.service`
- `systemctl --user cat horistic-pm2.service`
- `systemctl cat pm2-ubuntu.service`
- `pm2 jlist`

## preflight_snapshot

Antes de qualquer mudanca live, salvar snapshot local com timestamp:

```bash
TS="$(date +%Y%m%d_%H%M%S)"
mkdir -p "/home/ubuntu/.logs/resource-governor/pm2-hardening-$TS"
systemctl --user list-jobs > "/home/ubuntu/.logs/resource-governor/pm2-hardening-$TS/user-jobs.txt"

```

## tasks

### Task 1: choose canonical PM2 startup

Adotar como caminho suportado:

- PM2 user daemon do usuario `ubuntu`.
- `PM2_HOME=/home/ubuntu/.pm2`.
- PM2 binario `/home/ubuntu/.nvm/versions/node/v24.13.1/bin/pm2`.
- ATS ecosystem `/home/ubuntu/GitHub/Atius-Capital/ats/ecosystem.config.js`.
- Horistic ecosystem `/home/ubuntu/GitHub/Atius-Capital/horistic/ecosystem.config.js`.

Criar ou corrigir units versionadas em `modules/srv1-ops/systemd/` para subir
ecosystems reais, sem `KillMode=control-group` perigoso para processos ja
adotados pelo PM2 daemon.

### Task 2: replace broken path safely

Se `pm2-ubuntu.service` ainda apontar para `/home/ubuntu/ecosystem.atius.js`:

- Fazer backup do unit atual em
  `/home/ubuntu/.logs/resource-governor/pm2-hardening-$TS/`.
- Nao reiniciar `pm2-ubuntu.service` automaticamente.
- Documentar se ele deve ser desabilitado, substituido por user units ou
  corrigido para apontar ao ecosystem real.
- Aplicar apenas apos gate se houver risco de duplicar daemon.

### Task 3: drain stale jobs with gate

Antes de qualquer `stop`, `reset-failed`, `disable` ou `cancel`:

- Mostrar `systemctl --user list-jobs`.
- Confirmar que apps principais estao online via `pm2 jlist`.
- Confirmar portas criticas:
  - `127.0.0.1:3015` (`atius-web`)
  - `127.0.0.1:8050` (`horistic-api`)
  - `127.0.0.1:8015` (`atius-api`)
  - `127.0.0.1:8199` (`atius-webhook-signals`)
- Declarar impacto esperado.

Acoes permitidas sem gate humano: `daemon-reload`, `status`, `is-active`,
`cat`, `show`, `list-jobs`, escrita de unit versionada no repo.

Acoes que exigem gate: `systemctl --user stop`, `restart`, `disable --now`,
`kill`, `pm2 kill`, `pm2 resurrect`, `pm2 delete`, `systemctl restart
pm2-ubuntu.service`.

## acceptance_criteria

- Existe um caminho PM2 canonico documentado em repo.
- Nenhum unit suportado aponta para `/home/ubuntu/ecosystem.atius.js`.
- Jobs `ats-pm2.service`, `horistic-pm2.service` e `default.target` deixam de
  ficar presos ou ficam documentados como aguardando gate.
- PM2 apps criticos continuam online apos qualquer mudanca aplicada.
- `resource-governor-status.py` evidencia daemons duplicados e path quebrado.
