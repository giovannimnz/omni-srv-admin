  <action>Apply port migration using sed batch operations (per D-05, D-13, D-14). Order matters: sites-available first (symlink targets), then ports.conf, then reload.

Step 1 — Migrate sites-available (these are the real files; sites-enabled are symlinks):
```bash
sudo find /etc/apache2/sites-available/ -name '*.conf' -exec sed -i \
  -e 's/<VirtualHost \*:80>/<VirtualHost *:9080>/g' \
  -e 's/<VirtualHost \*:443>/<VirtualHost *:9444>/g' {} \;
```

Step 2 — Migrate ports.conf (Listen directives). Replace ALL Listen 80 and Listen 443 lines, including duplicates:
```bash
sudo sed -i \
  -e 's/^Listen 80$/Listen 9080/' \
  -e 's/^Listen 0\.0\.0\.0:80$/Listen 0.0.0.0:9080/' \
  -e 's/^\(\s*\)Listen 443$/\1Listen 9444/' \
  -e 's/^\(\s*\)Listen 0\.0\.0\.0:443$/\1Listen 0.0.0.0:9444/' \
  /etc/apache2/ports.conf
```

Also update mod_gnutls block if present (sed already handled by Step 2 patterns above — no additional action needed for mod_gnutls as it uses the same Listen 443 directive).

Step 3 — Test Apache config syntax BEFORE reload:
```bash
sudo apache2ctl configtest 2>&1
```

Step 4 — If configtest says "Syntax OK", reload (not restart — zero-downtime):
```bash
sudo systemctl reload apache2
```

Step 5 — Verify Apache2 is listening on new ports:
```bash
ss -tlnp | grep -E ':(9080|9444)\s'
```

Step 6 — Verify Apache2 is NOT listening on old ports:
```bash
ss -tlnp | grep -E ':(80|443)\s' | grep apache2
# This should return NOTHING
```

Step 7 — Quick content test on HTTP:
```bash
curl -s -o /dev/null -w "%{http_code}" http://localhost:9080/
# Should return 200, 301, 302, or 403 (not connection refused)
```

Step 8 — Quick content test on HTTPS (skip cert verification for self-signed test):
```bash
curl -sk -o /dev/null -w "%{http_code}" https://localhost:9444/
# Should return 200, 301, 302, or 403
```

If configtest fails, execute rollback: `/tmp/02-rollback-ports.sh`
