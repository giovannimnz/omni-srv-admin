<threat_model>
## Trust Boundaries

| Boundary | Risk | Required control |
|---|---|---|
| Upstream GitHub release -> local AppImage | Tampered or wrong-architecture binary | Select only `Obsidian-<version>-arm64.AppImage` from official releases and verify sha256/digest. |
| Installer -> vault/profile | Data loss or secret leakage | Backup/manifest before launch; do not read/copy note contents into repo docs/logs. |
| managed-apps -> fleet hosts | Accidental rollout | Manifest marks Obsidian local-only for `atius-srv-1`; no fleet apply in this phase. |
| Desktop launchers -> XRDP session | Session disruption | Use `xrdp-launch` and active display/x11vnc validation; do not open second XRDP or restart XRDP. |

## Threat Register

| ID | Severity | Disposition | Mitigation |
|---|---:|---|---|
| T-29.1-01 | high | mitigate | Reject non-official/non-ARM64 assets and validate sha256 before symlink switch. |
| T-29.1-02 | high | mitigate | Backup `~/.config/obsidian`, launcher files and safe vault metadata before any app launch. |
| T-29.1-03 | medium | mitigate | Keep updates manual-only; `upgrade` is plan-only unless `--yes` is passed. |
| T-29.1-04 | medium | mitigate | Quarantine Obsidian Snap remnants only after backup and verify no launcher points at Snap. |
</threat_model>
